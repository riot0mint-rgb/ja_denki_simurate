# 「訪問はご遠慮したい」と言われたときの手順 (VISIT_REFUSAL_PROCEDURE.md)

**対象**: 訪問に出る職員／支店の訪問先を割り当てる担当
**関連**: docs/VISIT_LOG_DESIGN.md, SECURITY.md, CLAUDE.md（ルール7・9）
**作成**: 2026-08-22

---

## なぜ、これがいちばん大事なのか

**一度お断りされたお宅に、別の職員がもう一度伺うこと。**
これが、JAの営業でいちばん信用を落とします。

- お客様から見れば「断ったのに、また来た」＝話を聞いていない組織
- 断った相手には、次の機会そのものが無くなります
- 苦情になれば、その地区全体で戸別訪問がやりにくくなります

しかも**取りこぼしは必ず起きます。** 断られた職員本人は覚えていても、
翌月に別の職員へ訪問先リストが回れば、その人は知らないからです。
**記憶ではなく、名簿で防ぐ**しかありません。

---

## 商談ナビは、どこまでやるか

| やること | どこ |
|---|---|
| 「今後の訪問はご遠慮したい」を選ぶと、確度を **E** にする | アプリ |
| 「その日のうちに名簿へ訪問不可を反映」「支店内で共有」と画面に出す | アプリ |
| 再訪の口実を**出さない**（追いかけさせない） | アプリ |
| **名簿に書き入れる** | **人**（この手順書） |

**アプリは何も覚えていません。** 画面を閉じれば消えます。
記録を残すのはJAが既に持っている名簿の側で、アプリはそこへ写す合図を出すだけです。

> なぜアプリに持たせないのか: この画面には認証がかかっておらず、
> 訪問先の住所が入った瞬間「誰でも開ける顧客名簿」になるためです。
> 詳しくは docs/VISIT_LOG_DESIGN.md。

## 手順

### 1. その場で（職員）

- [ ] **食い下がらない。** 「かしこまりました。失礼いたしました」で終える
- [ ] 資料を置いていかない（置いていくと「また来る」と受け取られます）
- [ ] 理由を尋ねない（お断りの理由を聞き出そうとするのが、いちばん嫌われます）
- [ ] 商談ナビの「今日の結果」で **「今後の訪問はご遠慮したい」** を選ぶ

> 言い方の例
> 「かしこまりました。以後うかがわないようにいたします。
> 　本日はお時間をいただき、ありがとうございました。失礼いたします。」

### 2. その日のうちに（職員）

**翌日に回さないでください。** 忘れます。

- [ ] 名簿（組合員管理システム／訪問先リスト）の該当のお宅に **「訪問不可」** を入れる
- [ ] 入れた日付と、自分の名前を添える
- [ ] 支店の担当者に口頭かメールで伝える（名簿への入力が承認制の場合は依頼する）

### 3. 翌営業日までに（支店）

- [ ] 名簿に反映されていることを、入力した本人以外が1人確認する
- [ ] **朝礼などで支店内に共有する**（あなた以外の職員が行ってしまいます）
- [ ] 訪問先リストを配る担当が、次回の割り当てから外す

### 4. 訪問先を割り当てるとき（毎回）

- [ ] リストを配る前に、**「訪問不可」を必ず除外する**

これが実際に効く仕掛けです。名簿に書いても、リストを作るときに見ていなければ意味がありません。

## 名簿に書く内容

**個人が特定できる形で残ります。これは個人データの取り扱いです。**
既に組合員名簿を運用している仕組みの中に置き、新しい台帳を作らないでください。

| 項目 | 例 | 備考 |
|---|---|---|
| 対象 | 組合員番号 | 住所やそのハッシュではなく、既にある番号で |
| 区分 | 訪問不可 | 「見送り」「検討中」とは**必ず分ける** |
| 記録日 | 2026-08-22 | |
| 記録者 | 氏名 | 誰に聞けば経緯が分かるか |
| 経緯 | 電気の戸別訪問時にお申し出 | **理由は書かない**（聞いていないため） |

⚠️ **「見送り」と同じ欄に入れないでください。** 見送りは再訪の対象、
訪問不可は対象外です。同じ欄だと、必ず混ざって再訪が起きます。

---

## いつまで訪問しないのか

**期限は設けません。** お客様から「もう来なくていい」と言われたのですから、
こちらの都合で期限を切る理由がありません。

- 解除は**お客様ご本人からのお申し出があったときだけ**
- 「1年経ったから」「担当が代わったから」で再訪しない
- 料金改定があっても、この方には**お知らせに伺いません**（商談ナビも口実を出しません）

---

## やってはいけないこと

| やってはいけない | なぜ |
|---|---|
| 別の職員が「担当が代わりましたので」と伺う | いちばん怒られる形。組織として断られています |
| 電話や郵送に切り替える | 訪問を断られたのであって、営業を歓迎されたわけではありません |
| 他の商品（共済・貯金）の勧誘に切り替える | 同じ人が来た、と受け取られます。他部門への共有は目的外利用の恐れもあります |
| アプリに住所を入れて管理する | この画面は認証がありません（docs/VISIT_LOG_DESIGN.md） |
| 理由を書き足す | 聞いていない理由を推測で書けば、それは事実ではありません |

## 月に一度の確認（支店）

- [ ] 今月「訪問不可」が何件増えたか
- [ ] **訪問不可のお宅への訪問が発生していないか**（発生していたら、外し忘れの原因を潰す）
- [ ] 商談ナビの記録（結果＝`refused_future`）の件数と、名簿の件数が合っているか

⚠️ **ここが合わなければ、書き写しが漏れています。** 手順そのものを見直してください。
件数だけを突き合わせる作業なので、個人情報を持ち出す必要はありません。

---

## 個人情報の取り扱いについて

「訪問を断られた」という記録は、**お客様の意思に関する情報**です。
通常の訪問履歴より慎重に扱ってください。

- 利用目的は「重複した訪問を避けるため」に限る（名寄せや他商品の勧誘に使わない）
- 見られる範囲を、訪問先を割り当てる担当と支店長に限る
- 保存期間と削除の扱いは、既存の組合員名簿の規程に従う
- 開示・訂正・利用停止のご請求には、既存の窓口で応じる

⚠️ 具体的な法令上の要件は、**JAの法務・コンプライアンス担当にご確認ください。**
この文書は運用の見取り図であって、法的な助言ではありません。
